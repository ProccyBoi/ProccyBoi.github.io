Try the interface

A push encoder, two keys and ten looks. Try the actual C screen renderer, compiled to WebAssembly. Press Play to hear original demo music.

Three sources. Ten looks. One tiny screen.

The player needs JavaScript and WebAssembly. On the device, a push encoder and two keys control the interface; Settings → Look changes its visual theme.

The pixels are from the firmware. Hardware events, library and radio data are simulated; browser music is separate from the STM32 audio pipeline. No FM reception or Bluetooth pairing happens here.

Audio architecture

Local files, radio and Bluetooth each arrive differently. The STM32 brings them into a common 48 kHz output domain for headphones and the built-in speaker.

The SDMMC peripheral reads a FAT filesystem. WAV and MP3 decoding feed a stereo FIFO; local playback is prefetched before display work. Supported WAV input is 16-bit mono or stereo at 8–96 kHz, converted to the 48 kHz output domain.

TLV320AIC3104 → 3.5 mm headphonesMAX98357A → mono speaker

Prioritise audio timing

Audio DMA has a 2 ms service window. An 8,192-frame stereo FIFO provides roughly 171 ms of buffering, with local playback filled ahead of display work. The screen only sends the region that changed.

Refine the enclosure

P2 develops the printed P1 enclosure: a larger battery bay, stronger port opening, removable display cradle and folding stand. The display flex and connector remain the critical physical-fit check.

Hardware and connections +
01

Control + scheduling

STM32H523VET6

Cortex-M33 configured at 160 MHz, with a 512 KiB flash / 272 KiB RAM linker layout. FreeRTOS runs the application task while circular DMA and interrupt callbacks sustain the audio stream; TIM6 supplies the HAL timebase.

02

Bluetooth receiving

Microchip BM83

Receives music from a phone over A2DP; there is no transmit path to wireless headphones. UART host control runs at 115,200 baud alongside a separate I²S2 PCM path.

03

Radio

Silicon Labs SI4705-D60

FM tuning and seek, with RDS station names and RadioText. Analogue left and right channels feed the codec ADC before joining the digital output path.

04

Conversion + listening

TLV320AIC3104 + MAX98357A

A stereo audio codec and headphone driver work alongside a mono I²S speaker amplifier. Bluetooth’s incoming 24-bit samples are reduced to 16-bit PCM in the current stream path.

05

Power + battery

BQ25895 + MAX17048

Power-path charging and fuel gauging are separate functions. USB-C provides power and detection. USB data lines are not routed to the MCU, so firmware programming uses SWD and files reach the player on the SD card.

06

Display + storage

ST7789 + 4-bit SDMMC

A 2-inch HS20HS072RX display runs in 320 × 240 landscape. The current library holds up to 64 tracks. A push encoder and two keys keep the interface usable without a touchscreen.

The display fit that shaped the enclosure +

The 2-inch display sits in a removable cradle behind a 1 mm clear lens. Its flex follows a U-fold studied at roughly 4.3 mm bend radius. Supplier contact dimensions and connector insertion geometry still need a real mating check.

Firmware decisions and trade-offs +

Two 9,600-byte one-bit masks track the current and previous screen; a theme palette turns them into RGB565 pixels. A dirty bounding rectangle reduces display traffic without changing the renderer between looks.

Bluetooth command ownership stays with a transaction until the matching response or profile boundary, so a late metadata response cannot become a new request. Settings use two CRC-protected records with retry backoff; persistence depends on a writable SD card.

The current sample-rate conversion is nearest-neighbour. Bluetooth drift uses basic frame dropping or duplication. These are implementation trade-offs, not claims of bit-perfect or transparent playback.

Development status

The 12 October 2026 firmware record includes a clean build, host tests, 130 renderer captures and flash readback verification. Those checks establish the tested image and behaviour; they do not replace extended listening or a P2 fit test.

Next on the bench

  • Listening: longer Bluetooth playback and metadata recovery, SD insertion and headphone switching, speaker output and stronger FM reception checks.
  • Power: reconcile charger and fuel-gauge voltage readings, then validate charging policy and battery runtime.
  • Assembly: print P2, mate the display flex, and check the actual battery, antenna, clearances and stand stability.
Read the verification notes +

All 130 renderer captures passed bounds and full-frame versus dirty-region equivalence checks. The documented binary was 154,836 bytes; populated HEX ranges matched flash readback, and the observed boot reported no application or DMA errors.

The largest reported first-party static stack frame was 16,616 bytes, below the 24 KiB gate. This does not measure live call-chain stack headroom. The observed BM83 firmware was 1.2, below the project’s 1.3+ production requirement; a short FIFO overflow occurred around wake, and metadata recovery needs a longer soak.
