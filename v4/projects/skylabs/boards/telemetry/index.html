01My contribution

STM32 aircraft PCB, sensor acquisition, binary logging and the aircraft side of the SX1262 telemetry link.

02The constraint

Keep a useful onboard record while sensors update at different rates and the radio carries only a smaller live subset.

03Design decisions

Store sensor presence and validity beside the readings, with missing measurements represented as NaN.

After the reference flight, buffer eight records per SD write and run sensor capture and logging before radio service. The logging target remains 40 Hz.

Gate EKF outputs using uncertainty and plausibility checks. The replay uses valid GNSS horizontal position and barometric height for the reference flight.

04What needed work

The F110211 flight averaged 20.27 Hz against the 40 Hz target and recorded 13,402 logging overruns. Its navigation EKF diverged, so the EKF path is excluded from the flight analysis.

05Evidence & validation

The published diagnostic covers 679.331 seconds and 13,772 usable aircraft records, with a 50 ms median log interval and zero SD write errors. These storage and timing results are reported separately.

06Current outcome

A later 150-second bench hold produced 146/146 fresh samples with continuous BNO and BME validity. The revised SD rate and EKF recovery still require confirmation in a fresh aircraft binary log.
