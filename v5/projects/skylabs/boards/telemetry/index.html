My contribution

STM32 aircraft PCB, sensor acquisition, binary logging and the aircraft side of the SX1262 telemetry link.

The task

Keep a useful onboard record while sensors update at different rates and the radio carries only a smaller live subset.

Design decisions

Store sensor presence and validity beside the readings, with missing measurements represented as NaN.

After the reference flight, buffer eight records per SD write and run sensor capture and logging before radio service. The logging target remains 40 Hz.

Gate EKF outputs using uncertainty and plausibility checks. The replay uses valid GNSS horizontal position and barometric height for the reference flight.

What the work

What has been checked

The published diagnostic covers 679.331 seconds and 13,772 usable aircraft records, with a 50 ms median log interval and zero SD write errors. These storage and timing results are reported separately.

Constraints and challenges

The F110211 flight averaged 20.27 Hz against the 40 Hz target and recorded 13,402 logging overruns. Its navigation EKF diverged, so the EKF path is excluded from the flight analysis.

Result and next step

A later 150-second bench hold produced 146/146 fresh samples with continuous BNO and BME validity. The revised SD rate and EKF recovery still require confirmation in a fresh aircraft binary log.

Read the detailed project notes

Sensors and logging

I developed this PCB around an STM32G474RET6. It brings together a u-blox GNSS receiver, BNO08x IMU, BME280 barometer, digital and analogue airspeed inputs, an HX711 strain interface, RTC, microSD storage and an SX1262 radio.

Each sensor has its own useful rate, failure mode and definition of “fresh”. The firmware stores presence and validity beside each measurement; missing values are NaN, not zero.

Firmware and logging

The IMU supplies acceleration and gyro reports at 100 Hz, attitude at 50 Hz and magnetometer data at 25 Hz. GNSS runs at 10 Hz. The aircraft logger samples at a 40 Hz target, batches eight binary records into each SD transaction and syncs once a second, which avoids making every sample wait for a card write.

A compact SX1262 packet carries the live subset to the ground station. The default profile sends at 22 dBm every 100 ms using 500 kHz bandwidth and spreading factor 5. Ground commands can start or stop the aircraft log, add an event marker and change the link profile without a USB cable in the aircraft.

After landing

The binary record keeps GNSS, environment, attitude, airspeed, strain and estimator output together. My replay tool reads that file into a synchronized 3D path, aircraft attitude, artificial horizon and engineering plots, while leaving the recorded values untouched.
