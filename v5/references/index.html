DESIGN / BROWSER / JAPANESE

UniBoard SPICE ↗

Denkoubu

Connects schematic editing, circuit simulation, perfboard layouts and two-layer PCB design in one browser workspace.

Worth borrowing: Clear stages make a complex process easier to follow, with a sample circuit as a starting point.

Boundary: The creator asks users to check circuits and layouts before building. Treat automatic results as proposals; some manual layout features require PRO access.

Creator’s guide · 12 Oct 2026 ↗

REFLOW / HARDWARE BUILD / JAPANESE

M5Stack Reflow Controller ↗

Kenta Ida · @ciniml

A modified toaster-oven controller using a thermocouple for temperature measurement and an SSR to control heater output.

Worth borrowing: Explain the relationship between sensing, control and physical output alongside the object.

Boundary: This is a physical build, not an online simulator. Its existence does not validate a generic reflow curve or recipe.

Schematics, enclosure and code ↗

Japanese maker provenance: creator’s ProtoPedia entry, 5 Sep 2021. No project-specific X post verified.

ASSEMBLY / OPEN DESIGN / JAPANESE

RP2040 alignment jig ↗

Atsushi Morimoto · @74th

A reusable fixture helps position the RP2040 during assembly. The build log shows revisions and links its KiCad files.

Worth borrowing: Show the constraint, the adjustment and the resulting design together. An iteration tells more than a polished render alone.

Boundary: Compatible alignment holes are needed in the target PCB. Reported ease of use is the maker’s experience.

PROTOTYPING / JAVASCRIPT / JAPANESE

CHIRIMEN ↗

CHIRIMEN Open Hardware community

Controls real hardware from browser JavaScript or Node.js, with tutorials for supported Raspberry Pi, micro:bit and other board configurations.

Worth borrowing: Let people choose their hardware or task before opening detailed instructions.

Boundary: Requires compatible hardware and setup. It is not a browser-only circuit simulation.

Project background ↗

Japanese-community source: official project site. It links its X account; no individual post is used as evidence here.

MECHANICAL MODELS / BROWSER / JAPANESE

STEP Model Combiner ↗

Kenta Ida · ciniml

Aligns multiple STEP models using selected faces, edges or vertices, then exports a combined model. The Japanese README documents browser-local processing.

Worth borrowing: Make selection visible and show exactly which parts an action connects.

Boundary: Export drops assembly hierarchy, part names and colors. Large models can exhaust memory. A practical tool, not a portfolio animation template.

REFLOW / HISTORICAL GUIDE / JAPANESE

Home Reflow Kit guide ↗

Switch Science

Documents a kit’s stencil alignment, paste application, component placement and reflow sequence, with a board bill of materials.

Worth borrowing: Explain assembly as distinct steps with a visible purpose. Boundary: This is historical kit documentation, not current stock information or a universal temperature profile.

02 / INTERNATIONAL INTERACTION REFERENCES

Make the explanation
part of the interaction.

These creators provide useful patterns for looking closer. Their inclusion does not imply Japanese origin or verified popularity on X.

EXPLAIN / USER-CONTROLLED MOTION

Mechanical Watch ↗

Bartosz Ciechanowski

Drag to change the view, reveal internals with a slider and scrub through a mechanism’s motion. Part names and diagrams share colors; animations can be paused globally.

Applied idea: Reveal a complex assembly in understandable stages while keeping a clear explanation nearby.

Boundary: A mechanism explanation is inspiration, not evidence that a long animation improves a portfolio.

Japanese developer seya’s reference notes ↗

Japanese-language discussion, not a verified X trail.

INSPECT / BROWSER / EARLY ALPHA

KiCanvas ↗

Thea “Stargirl” Flowers

An interactive browser viewer for KiCad schematics and boards.

Applied idea: Let the real design be inspectable. Give curious visitors a direct route from the overview into the underlying board.

Boundary: A viewer, not an editor. The README labels it early alpha and documents incomplete features and browser coverage.

Project documentation ↗

ASSEMBLE / BROWSER OUTPUT / OFFLINE

Interactive HTML BOM ↗

Open Scope Project · qu1ck

Links a searchable parts list to the PCB. Selecting a component finds its location; selecting a footprint finds its parts group. Generated HTML works offline.

Worth borrowing: Coordinate labels and geometry so selection answers a concrete question.

Boundary: Requires an export from supported design data. It does not validate electrical behavior or soldering.

Usage documentation ↗

SIMULATE / IMMEDIATE FEEDBACK

Circuit Simulator ↗

Paul Falstad · JavaScript port by Iain Sharp

Animated current, voltage colors and clickable switches expose changing circuit state. Examples offer a starting point.

Applied idea: An interaction should reveal a meaningful change, with text alongside visual cues.

Boundary: Its simulation behavior is not a claim we can transfer to a decorative PCB illustration.

EXPLAIN / READING & NAVIGATION

Putting the “You” in CPU ↗

Lexi Mattick & Hack Club

A chapter-based explanation of program execution, with direct navigation, a suggested jump for experienced readers and one-page/PDF alternatives.

Applied idea: Offer a quick path and a deeper path. Boundary: This informs reading structure; it is not a PCB fabrication or reflow simulation.

03 / DECISIONS FOR V5

Borrow the principle.
Keep the evidence.

The aim is to make the work easier to reach and understand. These are design hypotheses and standards-based choices, not measured claims of higher engagement or better hiring outcomes.

What the research changes in this portfolio
DecisionGroundingWhat to check
Use real CAD; label the illustrationKiCanvas makes source designs inspectable. The telemetry case study supplies the project context.Geometry and placement stay distinct from illustrative paste, solder appearance and assembly order. No invented temperature readings.
Keep native scrolling and a skip linkW3C: keyboard access. Animation follows the document; it does not capture wheel or touch input.Reach projects directly. Tab, Enter, Page Down and browser navigation still work.
Load detail when needed; keep a static viewMDN: progressive enhancement and visibility observation.The board image, explanation and links remain useful without JavaScript or WebGL. Heavy scene assets wait until needed.
Link to the visitor’s next taskCPU Land’s navigation and CHIRIMEN’s board-specific paths offer clear entry points.Find the board, try firmware, open the CV or contact Andrew without completing an animation.
Respect reduced motionW3C: animation from interactions addresses nonessential motion; it is a WCAG AAA criterion.Show a finished-board view, retain the explanation and remove the long animation runway when reduced motion is requested.

The next useful test is simple: can a visitor explain what Andrew builds, find the telemetry board and open the CV? Also check whether the assembly is mistaken for measured manufacturing data. Those observations would support a stronger UX claim than visual polish alone.
